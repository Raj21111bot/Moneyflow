# Money Flow Dashboard — Session Summary

Continuity doc for picking this project back up in a fresh conversation. Written 2026-07-19.

## What this is

A self-contained, offline-capable HTML dashboard (`docs/index.html`) showing NSE (National Stock Exchange, India) sector/stock money flow — traded value and **delivery value** (delivered qty × avg price, the "real money" proxy vs. intraday churn) — built from NSE's daily bhavcopy files. No backend framework, no build step: one HTML file with inline CSS/JS, reading a JSON data file.

**Project folder:** `d:\New folder\moneyflow\` (also backed up to OneDrive at `OneDrive - Alghanim\MoneyFlow-Backup` as of 2026-07-19, ahead of a laptop swap — see "Migration status" below).

**To view it:** double-click the "NSE Money Flow" desktop shortcut, or manually open **http://127.0.0.1:8000** (not `localhost` — see Gotchas).

## The three pages

**Heatmap** (default view) — Sector → Industry → Stock drill-down modal (click through), values in ₹ Cr, cells highlighted when above/≥1.5× their own 30-day average. Clicking a stock opens a date-wise bar chart (traded value or delivery value, toggle at top) covering the full ~160-day history, with Screener.in / TradingView / Volume icons in the modal header. Industry-level classification isn't real (NSE's per-symbol classification API is blocked from this network — see Gotchas), so "industry" currently just falls back to the sector name.

**Signals** — Screener for delivery-spike stocks (config: multiplier ≥ Avg30, min days hit in last 5 sessions, min avg turnover to skip illiquid names). Each row has: Screener.in link, TradingView chart link (deep-links straight to the chart via `tradingview.com/chart/?symbol=NSE:{SYM}`, not the generic symbol page), a Volume icon (opens the same in-dashboard chart as Heatmap), a **Trend (D·W·M)** column — three small colored badges showing that stock's own Daily/Weekly/Monthly accumulation/distribution read (see methodology below), and a computed score. Has an **Export CSV** button that respects current filters.

**Sectors** — Ranks all 23 real sectors by accumulation/distribution, with a Daily/Weekly/Monthly period toggle. Green rows = accumulation (money flowing in), orange = distribution (flowing out), intensity in two bands each (≥1.1×/≥1.5× and ≤0.9×/≤0.67×). Click the **+** icon next to any sector to expand its stocks **inline** (Excel-style grouping — not a popup), sorted by delivery value, each with the same Screener/TradingView/Volume icons and its own D/W/M-consistent classification badge. Multiple sectors can stay expanded simultaneously; state persists until explicitly collapsed (**−**) or the page is refreshed. Has its own **Export CSV** button that mirrors on-screen state exactly — if a sector is expanded, its stock rows export too, immediately under that sector's summary row.

### Accumulation/distribution methodology (shared logic, `classifyFlow`/`flowForPeriod` in index.html)

Current period's average delivery value vs. that same sector/stock's own average over the *rest* of the available history window (not a fixed external benchmark — self-relative). Daily = last 1 session, Weekly = last 5, Monthly = last 21, baseline = everything else in the ~160-day window. Thresholds: ≥1.5× "Strong accumulation", ≥1.1× "Accumulation", ≤0.67× "Strong distribution", ≤0.91× "Distribution", else "Neutral". Same function powers both the Sectors page and the Signals page's D/W/M column — verified against real data to produce genuinely different labels per stock/timeframe (not hardcoded).

## Data pipeline

- `scripts/build_sector_map.py` — builds `data/sector_map.csv` (symbol → sector/company) from NSE's Nifty Total Market constituent list. The `--enrich` flag (per-symbol industry drill-down) **does not work** from this network — NSE's `quote-equity` API returns 403 for everything, confirmed by testing. Don't bother re-running it with `--enrich`; it'll spin uselessly. Currently ~2,300+ symbols mapped, non-Nifty-Total-Market stocks bucket into "Others" (~1,950 stocks and growing).
- `scripts/fetch_daily.py` — downloads NSE's `sec_bhavdata_full_DDMMYYYY.csv` bhavcopy from `nsearchives.nseindia.com` (this specific subdomain is reachable even though `www.nseindia.com` itself 403s from this network), aggregates by sector/industry/stock, merges into `docs/data/history.json`. `MAX_DAYS_KEPT = 160` (rolling window, ~7+ months). Run with `--backfill N` to seed N trading days, or no args for the normal daily run — **as of 2026-09-22 this walks backward from today filling in every weekday missing from history** (capped at 30 attempts, stops once it reaches a date already recorded), so a laptop that was off/asleep for several days catches up on all of them the next time it runs, not just today. A day skipped due to a genuine network failure (vs. a clean "not published yet") stays missing and gets retried automatically on the next run.
- `scripts/daily_refresh.ps1` — wrapper Task Scheduler actually runs. Forces UTF-8 output (Windows console mangles the ₹ symbol otherwise), calls `fetch_daily.py` via a **hardcoded Python path** (see Gotchas for why), logs to `logs/`, then makes a best-effort `git add`/`commit`/`push` attempt that's a complete no-op today (no GitHub remote configured yet — see "Deferred: GitHub Pages" below). Never fails the overall task even if the git step can't run.
- **Scheduled task "MoneyFlow Daily Refresh"**: Mon–Fri, two triggers — **7:00 AM** (morning catch-up, grabs yesterday's data via fetch_daily's natural fallback if the evening run was missed) and **5:00 PM** (primary, timed for after NSE publishes ~6:30–7 PM IST ≈ 5 PM Kuwait local time). Has `StartWhenAvailable` and `WakeToRun` both enabled — the laptop was found sleeping through the 5 PM trigger once already (see Gotchas), so wake timers were enabled system-wide (`powercfg` RTCWAKE set to Enable on both AC/DC) plus the task's own wake-to-run flag. **Never actually verified live** (user declined the sleep test) — worth checking this actually works if data goes missing again.
- `scripts/launch_dashboard.ps1` — desktop shortcut target. Starts the local `python -m http.server 8000` if not already running, opens `http://127.0.0.1:8000` (not `localhost`).
- `scripts/setup_new_machine.ps1` — one-shot bootstrap for a fresh machine: finds real Python (skips the WindowsApps alias stub), installs `requests`, patches the hardcoded Python path in the two helper scripts, registers the scheduled task, creates the desktop shortcut. This is the go-to script after restoring from backup.

## Gotchas worth knowing (cost real debugging time — don't rediscover)

1. **`localhost` resolves via IPv6 first on this machine and stalls ~21 seconds** before falling back to IPv4, regardless of payload size (confirmed: a tiny 34KB file took the same 21s as a 9.6MB one). Always use `127.0.0.1` instead. All our scripts already do this.
2. **Task Scheduler doesn't see the same `python.exe` as an interactive session.** The interactive PATH resolves to a WindowsApps "alias stub" that fails silently (zero output, no error) when launched by Task Scheduler (no interactive session to activate through). Fix: hardcode the real interpreter path (`C:\Users\rajesh.santhanam\AppData\Local\Python\pythoncore-3.14-64\python.exe` on the old laptop — **will be different on a new machine**, hence `setup_new_machine.ps1` re-detects and patches it) and only fall back to PATH search as a secondary option.
3. **This network blocks a lot.** `www.nseindia.com` (main site, base for cookies) returns 403, but `nsearchives.nseindia.com` (bulk archive files) works fine — a session GET to the main site fails silently and that's expected/harmless, the archive fetch still succeeds. Separately, `github.com`, `gitlab.com`, and `bitbucket.org` are ALL blocked (SNI-level, not just github-specific) from the office Ethernet network — confirmed by testing all three. Worked fine once connected to a secondary Wi-Fi network alongside office Ethernet.
4. **NSE's `quote-equity` API (used for industry-level classification) is blocked entirely** — confirmed 403 even bypassing cert validation. No workaround found; industry drill-down isn't real, just falls back to sector name.
5. **PowerShell tool calls don't persist shell state (env vars, PATH) between separate invocations** — only working directory persists. Any script needing an updated PATH (e.g. right after installing something with winget) must re-set `$env:Path` from the registry at the start of *every* subsequent call, not just once.
6. Installing Git for Windows changed PATH ordering such that bare `python` now resolves to a *different* install (`Python312`, no `requests` installed) than the one everything was built against (`pythoncore-3.14-64`, has `requests`). Always use the full hardcoded path for ad-hoc manual testing, not bare `python`.
7. Python's built-in `http.server` is fine for a ~10MB JSON file over loopback (confirmed ~0.2s once the localhost/IPv6 issue above is avoided) — gzip compression was investigated and found unnecessary once the real bottleneck (IPv6 stall, not payload size) was identified.

## Daily automation outage & fix (2026-09-22)

Heatmap had gone stale since 2026-09-18. Root causes found:

1. **Machine's timezone silently drifted from India Standard Time to Arab Standard Time (Kuwait, UTC+3)** at some point after the 2026-08-21 migration — cause unknown (not `tzautoupdate`-driven that we could confirm). Harmless in itself (Task Scheduler stores an absolute UTC instant per trigger, so the *real-world* fire time didn't actually shift), but confusing to read in Task Scheduler.
2. **The laptop uses Modern Standby and slept through both the 2026-09-21 evening and 2026-09-22 morning triggers** — confirmed via `Get-WinEvent` Kernel-Power logs: it entered sleep ~19:xx on 9/21 and didn't resume until 13:10 on 9/22 (a keyboard/lid wake by the user, not the task's `WakeToRun`, which appears not to actually work on this machine's Modern Standby implementation — matches the never-live-verified concern already noted in the "Gotchas" section from the old laptop).
3. **The scheduled task was configured to refuse running on battery and to hard-stop if switched to battery mid-run** (`DisallowStartIfOnBatteries` / `StopIfGoingOnBatteries`, both default `true`) — the 13:16 catch-up run's `LastTaskResult` was `0xC000013A` (STATUS_CONTROL_C_EXIT), consistent with exactly this happening.
4. **`fetch_daily.py` was mislabeling network/SSL failures as benign "holiday/weekend" skips** — a transient SSL error reaching `nsearchives.nseindia.com` got logged identically to a genuine non-trading-day, making the real cause invisible in the logs. **Fixed**: `fetch_bhav` now raises `FetchFailed` on request errors instead of returning `None` like a clean no-data case; `main()` tracks this and exits non-zero with an `[error]` line if a run made zero progress due to a real failure, instead of silently reporting success.

**What was changed:**
- Scheduled task rebuilt as **three separate tasks** (not one task with three triggers) — `MoneyFlow Daily Refresh` (16:45 local = evening primary), `MoneyFlow Morning Catchup` (04:30 local = 7 AM IST catch-up), both Mon–Fri. A third `MoneyFlow Logon Refresh` (fire on any logon, as a Modern-Standby safety net) was attempted but **could not be created** — seems this Windows install's UAC/CIM permissions (or Claude Code's own shell sandbox) reject `ONLOGON`-trigger and any XML-based task registration with "Access is denied", while plain flag-based `schtasks /create` for time triggers works fine. Root cause not fully isolated; if this needs revisiting, try from an elevated/admin PowerShell window instead of Claude Code's shell.
- **`DisallowStartIfOnBatteries` / `StopIfGoingOnBatteries` could NOT be turned off programmatically** for the same reason (both `Set-ScheduledTask` and XML-based `Register-ScheduledTask`/`schtasks /create /xml` hit "Access is denied"; only the no-XML flag-based create path works, and it has no flag for these settings). **Manual step still needed**: open Task Scheduler (taskschd.msc) → find both MoneyFlow tasks → Properties → Conditions tab → uncheck "Start the task only if the computer is on AC power" and "Stop if the computer switches to battery power". Two minutes, one-time, needs to be done by hand.
